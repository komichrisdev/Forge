## Runtime configuration and transport

The server reads variable names `SWARM_DB_PATH` and `SWARM_RUN_DIR`. When they
are absent, `src/data.ts` uses the documented user-local Swarm runtime
locations. `NODE_ENV` is supplied by the unit. This map records no values.

`src/main.ts` binds only `127.0.0.1:8790`, routes all MCP methods at `/mcp`, and
creates a stateless `StreamableHTTPServerTransport` with JSON responses. It
returns 404 for other paths and a bounded JSON-RPC `-32603` response when an
uncaught HTTP handler error occurs before headers are sent. The only normal
application log is the startup listen message. No per-tool timeout is
configured in this service.

## Tool and handler map

All tools are registered in `src/server.ts`, use the same output schema
(`{data: object}`), and advertise read-only, non-destructive, closed-world
annotations.

| Tool | Input | Read-only handler |
| --- | --- | --- |
| `get_swarm_status` | Empty object | `SwarmData.status()` |
| `list_swarm_runs` | Bounded pagination plus status, task mode, model and date filters | `SwarmData.listRuns()` |
| `get_swarm_run_summary` | Validated `runId` | `SwarmData.runSummary()` |
| `get_swarm_run_details` | Validated `runId` | `SwarmData.runDetails()`; large detail is widget-only metadata |
| `list_swarm_models` | Bounded pagination, search and model filters | `SwarmData.listModels()` |
| `get_swarm_model` | Exact validated `modelId` | `SwarmData.model()` |
| `render_swarm_control` | Empty object | Status plus bounded run/model reads for widget metadata |

The shared `safe()` boundary returns declared `PublicError` text and replaces
unexpected exceptions with `Swarm data could not be read.` Input validation
and unknown-tool errors are generated by the MCP SDK as JSON-RPC `-32602`.
Exact descriptions, titles, schemas, annotations, capabilities and resource
metadata are captured in
`chatgpt_app/test/fixtures/mcp-live-contract.json`.
